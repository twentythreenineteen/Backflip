# Application UI source survey

Static source review, 2026-10-31; four different public FAPs, current default-branch revisions resolved on that date. These are empirical examples, not official design or API standards. No binaries built, no pixels measured on hardware, no usability or accessibility testing performed. Examples do not prove firmware-version compatibility. Full commit SHAs and line ranges below are immutable GitHub links.

## Layout, clipping and state

- **GhostTag** (tracker detector), commit `b86e4b449cfebd3baec2d92d9697465e75ffa5c2`: its device-list author documents a real regression: four 13-pixel rows beginning at y=13 extended beyond y=63, cutting off the highlight and descenders. The replacement uses `LIST_TOP=13`, four rows of `ROW_H=12`, occupying rows 13–60; it reserves columns 124–127 for the scrollbar ([device_list_view.c:8–18](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/device_list_view.c#L8-L18)). Validate every rectangle's actual extent (`x + width - 1`, `y + height - 1`) and text glyphs separately; baseline alone is not the full text bounds.
- The same view puts 10px type and warning icons at row y+1, text at baseline y+9, selection fill behind the row with white foreground, then restores black; a scrollbar is drawn separately ([lines 147–176](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/device_list_view.c#L147-L176)). Icon dimensions and row-height constraints must be considered together.
- **Counterexample to assuming alignment prevents collision:** the source comments that right-alignment means a long name cannot collide, but the row draws the name at x=14 and the duration right-aligned at x=78 with no width check or clipping between them ([lines 15–18, 160–167](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/device_list_view.c#L15-L18), [row code](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/device_list_view.c#L160-L167)). The source does not establish that arbitrary labels fit; measure or bound both strings.
- **PowerMeter** (sensor dashboard), commit `4b6523a686222185ccc84daefa8b680bec6f92cf`: primary title at (0,8), secondary source label right-aligned at x=128, separator at y=10. It measures the source string with `canvas_string_width` before placing its pulse indicator ([pm_view.c:5–15](https://github.com/nhecker/flipperzero-powermeter/blob/4b6523a686222185ccc84daefa8b680bec6f92cf/pm_view.c#L5-L15)). The chart combines stats in one string and uses the labeled version only if its measured width is ≤126, otherwise the shorter triple ([lines 182–193](https://github.com/nhecker/flipperzero-powermeter/blob/4b6523a686222185ccc84daefa8b680bec6f92cf/pm_view.c#L182-L193)). This is measured fallback, not evidence that the fallback itself always fits. Alignment anchors such as x=128 are not themselves a claim that pixel column 128 exists.
- Chart heights are clamped to the plot height; an explicit empty-column sentinel breaks lines across missing data rather than plotting fake zeroes. Its author chooses line rather than bar marks when the vertical axis is fitted ([pm_view.c:160–179](https://github.com/nhecker/flipperzero-powermeter/blob/4b6523a686222185ccc84daefa8b680bec6f92cf/pm_view.c#L160-L179)).
- **Trivia Zero** (localized quiz), commit `8ce7fc4f86dca42edc0244f1effa68c89bb80ffd`: word wrapping uses a 21-character maximum and breaks long words ([question_view.c:18–47](https://github.com/Endika/flipper-trivia-zero/blob/8ce7fc4f86dca42edc0244f1effa68c89bb80ffd/src/ui/question_view.c#L18-L47), [lines 74–78](https://github.com/Endika/flipper-trivia-zero/blob/8ce7fc4f86dca42edc0244f1effa68c89bb80ffd/src/ui/question_view.c#L74-L78)). This is a character-count heuristic, not pixel-based fitting; proportional glyph widths and translated text can violate a fixed visual width. The body allows six lines at baselines 20, 28, 36, 44, 52, 60, while the footer is top-aligned at y=56 ([lines 102–130](https://github.com/Endika/flipper-trivia-zero/blob/8ce7fc4f86dca42edc0244f1effa68c89bb80ffd/src/ui/question_view.c#L102-L130)). A sixth line may collide with the footer; inspect rendered glyphs for real inputs instead of copying these constants.

## Navigation, overlays and semantics

- GhostTag's `reframe` handles zero entries before calculating `count - 1`, clamps selection and adjusts the visible window to keep it on-screen; `elements_scrollbar` indicates position ([device_list_view.c:176–191](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/device_list_view.c#L176-L191)). Its empty state distinguishes live/listening, absent board, demo starting, and idle with next steps ([lines 95–143](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/device_list_view.c#L95-L143)); zero data and a disconnected source are not presented as the same situation.
- PowerMeter's input callback maps left/right to wrapping pages, short OK to settings, long OK to session reset and short Back to exit ([pm_view.c:277–309](https://github.com/nhecker/flipperzero-powermeter/blob/4b6523a686222185ccc84daefa8b680bec6f92cf/pm_view.c#L277-L309)). Trivia Zero maps short OK to reveal, left/right to previous/next, up/down to scroll, Back to menu ([question_view.c:133–162](https://github.com/Endika/flipper-trivia-zero/blob/8ce7fc4f86dca42edc0244f1effa68c89bb80ffd/src/ui/question_view.c#L133-L162)). These are app-specific navigation schemes, not universal key assignments; distinguish short/long/repeat and avoid hiding destructive actions.
- **NW Crawl** (roguelike), commit `7ffcd194734cb906f8272007103498482a929cf6`: the message bar moves to the bottom of the playfield when the player is near the top, otherwise sits at the top, minimizing occlusion; it paints a white backing before drawing a rule and text, then reserves an inverse HUD at the bottom ([nw_crawl.c:1928–1950](https://github.com/rseufert/nw_crawl/blob/7ffcd194734cb906f8272007103498482a929cf6/nw_crawl.c#L1928-L1950)). Its title positions three 8×8 bitmap sprites alongside centered labels ([lines 1710–1726](https://github.com/rseufert/nw_crawl/blob/7ffcd194734cb906f8272007103498482a929cf6/nw_crawl.c#L1710-L1726)). Draw order and contrast matter as much as coordinates.
- GhostTag's alert view uses a full-width 14px inverted banner, a warning triangle bounded to y=16–47, a detail column and footer ([alert_view.c:25–34, 40–62](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/alert_view.c#L25-L62), [lines 78–103](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/alert_view.c#L78-L103)). It alternates banner states; source comments discuss an earlier strobe concern ([lines 6–10](https://github.com/at0m-b0mb/GhostTag-FlipperZero/blob/b86e4b449cfebd3baec2d92d9697465e75ffa5c2/views/alert_view.c#L6-L10)). Do not treat its revised flash rate as proven safe; avoid unnecessary flashing and test accessibility.

## Practical synthesis

Design within the actual view dimensions and reserved system areas; confirm against official API and attachment layer separately. Allocate explicit header/body/footer and scrollbar bounds; measure variable strings with the active font and provide a bounded truncation, wrapping, or scrolling policy. Check tall glyphs, long translations, empty data, list boundaries, overlays, icon dimensions and both short/long key events. Prefer evidence from screenshots/device tests over geometry inferred from source alone.
