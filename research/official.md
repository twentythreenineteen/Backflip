# Official Flipper FAP/UI research

Research date: 2026-10-31. Scope: official Flipper Zero firmware and uFBT sources, not third-party forks or universal design mandates. Firmware sources below are pinned to **dev commit `9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a`**, committed 2026-10-30; uFBT README is pinned to **dev commit `4c603daa164430d791cb58ef019f18721ced7f0d`**, committed 2026-01-29. These are source snapshots, not claims about an installed device's release. Check the target firmware/SDK before relying on any signature, module, export, or deprecated API.

## 1. Display geometry and layout

**Verified source facts.** The firmware's *internal* GUI geometry declares a 128×64 display, status bar height 13, and window origin `(0,13)` with size 128×51. `GuiLayerFullscreen` has no status bar; `GuiLayerWindow` displays one. These exact offsets are implementation details at the pinned revision, **not public constants to import**. Use `canvas_width()` and `canvas_height()` to get the actual canvas frame dimensions and draw in its local coordinates. Viewport orientation can also rotate or flip the rendering context. [GUI internal geometry](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/gui_i.h); [GUI layers](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/gui.h); [canvas frame implementation](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/canvas.c); [viewport orientation](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/view_port.h).

**Design advice, not an official pixel-spacing rule.** For a horizontal fullscreen frame, valid pixel coordinates are x `0..127` and y `0..63`; window-local y is `0..50` at this revision. Treat a box at `(x,y)` of `w×h` as occupying x `x..x+w-1`, y `y..y+h-1`, and test all foreground art and text (including descenders) against the actual frame. Reserve separate regions for title, content and action hints, and test long strings, empty state, selection and bottom edge. Do not assume a fixed 64px height in window mode. Alignment anchors are not necessarily painted pixels.

## 2. Text, drawing, icons

**Verified source facts.** [`canvas.h`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/canvas.h) defines `FontPrimary`, `FontSecondary`, `FontKeyboard`, `FontBigNumbers`; drawing colors white, black and XOR; canvas dimensions, current font height, font metrics, string width, drawing primitives and images. `canvas_draw_str(canvas, x, y, text)` places text at a **baseline**, not top-left. `canvas_draw_str_aligned` takes `AlignLeft/Right/Center` horizontally and `AlignTop/Bottom/Center` vertically. At this revision, its [implementation](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/canvas.c) subtracts string width or half-width from x, and adds ascent or half-ascent to y for top/center; bottom leaves y as the baseline. Descenders are not included in that ascent-based vertical alignment. Invalid axis/alignment combinations crash. String width is measured with the active font's UTF-8 width; the drawing backend uses UTF-8, but glyph coverage depends on the selected font.

- **Advice:** select the font before measuring; use `canvas_string_width()` rather than character counts. `canvas_current_font_height()` and `canvas_get_font_params()` help plan line height, but validate actual glyph bounds visually. `canvas_draw_str_aligned(canvas, canvas_width(canvas)/2, ..., AlignCenter, ..., text)` is a convenient horizontal anchor; reserve width and account for integer rounding and descenders, not a promise of pixel-perfect visible bounding-box centering.
- **Verified:** `canvas_draw_icon()` accepts an `Icon*` and coordinates; [`icon.h`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/icon.h) exposes `icon_get_width()` and `icon_get_height()`. **Advice:** to center an icon in region `(x,y,w,h)`, use `x + (w - icon_width)/2`, `y + (h - icon_height)/2`, checking that dimensions fit before subtracting, especially with unsigned sizes. For icon+text rows, measure both and spacing as a group; align text on its baseline separately from the icon's top edge.
- **Verified:** [`elements.h`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/elements.h) provides multiline, button, scrollbar, fitting and scrolling helpers. [`elements_string_fit_width`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/elements.c) mutates a `FuriString` and appends `...` when fitting; its pinned implementation subtracts the ellipsis width from unsigned `width` and removes string units one at a time. **Advice:** do not assume tiny widths smaller than `...` or arbitrary multibyte truncation are safe; guard and test them on the target SDK, or use an explicitly UTF-8-aware policy. Test whether the chosen font contains required glyphs. Avoid silent clipping; choose explicit truncation, scrolling, wrapping or another view.

## 3. Views, input and lifecycle

**Verified source facts.** A [`ViewPort`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/view_port.h) binds draw and input callbacks, **both called from the GUI thread**; unregister the viewport from the GUI before freeing it. [`View`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/view.h) also has GUI-thread draw/input callbacks; input callback returns handled/not handled. Its locking model guards shared model access with a mutex; lock-free is intended for atomic types and/or situations where partial updates do not matter. `with_view_model` obtains and commits model access; commit's update flag controls redraw notification.

[`ViewHolder`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/view_holder.h) connects a single View; its current view must be unset before freeing. [`ViewDispatcher`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/view_dispatcher.h) connects/switches multiple views, runs an event loop until stopped, and requires all added views be removed before it is freed. Its custom, navigation and tick callbacks are documented as running on the thread that called `view_dispatcher_run`, in contrast with GUI-thread View draw/input callbacks. Queue support is built in at this snapshot; `view_dispatcher_enable_queue()` is deprecated. The official [ViewDispatcher example](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/examples/example_view_dispatcher/example_view_dispatcher.c) demonstrates GUI record acquisition, attaching, registering, switching, running, stopping on Back, removing views, freeing modules and closing the record. The [single-view example](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/examples/example_view_holder/example_view_holder.c) uses a scrollable TextBox and Back-to-exit.

[`InputEvent`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/input/input.h) has key and type: debounced Press/Release, Short after qualifying release, Long, and Repeat after Long. **Advice:** select one event type per action to avoid a Press+Short double-action; define Back behavior at each screen and test both short and long presses. Do not claim callbacks are ISRs. Keep GUI-thread callbacks bounded; offload blocking I/O/long work, use proper synchronization or event dispatch, and stop/join workers before destroying their state. Select a single ViewHolder, dispatcher, or low-level viewport to suit the UI; use stock modules such as [Submenu](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/modules/submenu.h), [TextBox](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/modules/text_box.h), and [Widget](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/services/gui/modules/widget.h) when they solve the interaction.

## 4. Manifests, resources, compatibility

**Verified source facts.** [`application.fam`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/documentation/AppManifests.md) is a Python-syntax `App(...)` build manifest. Its documentation says only `appid` and `apptype` are universally mandatory; a functional external app also needs an appropriate entry point. An [official example](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/examples/example_view_dispatcher/application.fam) specifies `appid`, name, `FlipperAppType.EXTERNAL`, entry point, `requires=["gui"]`, and category. `stack_size` is bytes: too little can overflow; too much reduces heap. `fap_icon` is a **1-bit 10×10 PNG menu icon**, not a UI image size requirement. `fap_icon_assets` points to private in-app image assets; [`AppsOnSDCard.md`](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/documentation/AppsOnSDCard.md) says to include `"{APPID}_icons.h"`. Follow [asset naming](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/assets/ReadMe.md): `NAME_VARIANT_SIZE`, size mandatory; compiled images get `I_`, animations `A_`. Unused assets are not stripped according to that source.

File assets provided with the app and persistent user data differ: official examples recommend `APP_ASSETS_PATH("file")` and `APP_DATA_PATH("file")`, respectively, rather than hard-coded SD paths. See [assets example](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/examples/example_apps_assets/README.md) and [data example](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/applications/examples/example_apps_data/README.md). The assets example contains a `/data` typo in prose: use its explicit macro, not that example path.

A FAP is ELF-based metadata/resources and is loaded to RAM, reducing available heap. The app loader checks API compatibility, including matching major API version; build-time warnings can flag missing imported symbols. External apps can use only exported firmware functions/variables, not every declaration or private header; the [target API symbol list](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/targets/f7/api_symbols.csv) shows exports for this specific snapshot. API major/minor versions track breaking changes/additions, but a major match alone is not a guarantee of all symbols or runtime compatibility. **Advice:** build with the SDK for the intended firmware, verify the actual exported symbols, target and firmware on device, and test each supported release/fork rather than implying that an arbitrary FAP runs on all versions.

## 5. Build, test, and evidence limitations

**Verified source facts.** Official [uFBT README](https://github.com/flipperdevices/flipperzero-ufbt/blob/4c603daa164430d791cb58ef019f18721ced7f0d/README.md): install on Windows with `py -m pip install --upgrade ufbt`; run `ufbt` in the app manifest directory to produce `dist`, and `ufbt launch` to upload/start on USB. First use defaults to the official release SDK; `ufbt update --channel=[dev|rc|release]`, `--branch=...`, or `--local=...` select alternatives. `ufbt lint`/`format` operate on application sources. Debugging requires firmware distributed with the SDK. Full firmware workflows in [FAP documentation](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/documentation/AppsOnSDCard.md) include `./fbt fap_{APPID}`, `./fbt build APPSRC=...`, and `./fbt launch APPSRC=...`. Official [firmware unit tests](https://github.com/flipperdevices/flipperzero-firmware/blob/9981d9d4aa5ec7b14bb46cf15763dd293a7dec6a/documentation/UnitTests.md) run on hardware using a specially built/flashed firmware and CLI `unit_tests`; this is a firmware test harness, **not** a claim that `ufbt` automatically runs standalone FAP tests.

**Recommended validation:** build against the selected target SDK; exercise navigation, Back, event types, smallest/longest supported strings, glyph coverage, full-screen/window bounds, missing storage and repeated open/close on actual hardware. Capture screenshots where possible and verify descenders, focus/selection, action hints and exact edge bounds. Test real resource loading and worker shutdown; record firmware/SDK versions and outcomes. Device-only observations must not be invented.
